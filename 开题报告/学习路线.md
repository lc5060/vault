## 模块一：AI 基础（补短板，够用即停）

**目标**：能看懂、跑通、微调一个现成策略模型，不追求懂原理推导。

- **NumPy**：创建数组、索引/切片、reshape、运算与广播。当手册查即可（菜鸟教程 NumPy 篇）。
- **PyTorch 8 个最小点**：Tensor、device（`.to('cuda')`）、autograd、nn.Module、损失 + 优化器、训练循环（forward→loss→backward→step）、Dataset/DataLoader、模型保存/加载（torch.save / load_state_dict）。
- **Transformer / VLM 概念**（只理解、不推导）：attention、ViT、KV cache、flow-matching 是什么、action chunk 是什么。
- **HuggingFace 生态**：下权重（from_pretrained）、读 config、跑推理。

**验收**：独立写一个能训练的分类器；能把一个候选策略模型推理跑起来（具体模型待定）。

**资源**：小土堆《PyTorch 深度学习快速入门》（B站）、李沐《动手学深度学习》、PyTorch 官方 60 Minute Blitz、3Blue1Brown（attention 部分）、李宏毅机器学习。

## 模块四：Linux 实时运行时（✅ 确定 · 主场 · 现在就练）

**目标**：把控制环的调度抖动压到 μs 级，并能量化报告。

**练习硬件**：不需要 Orin/RK3588，任意 Linux 机器（笔记本/台式机/树莓派）都能练，方法通用。

### 4.1 PREEMPT_RT 内核
- **概念**：标准内核（自愿抢占）vs PREEMPT_RT（完全抢占）的区别；内核态抢占、优先级继承（PI）、RCU 在 RT 下的处理。
- **实操**：打补丁编译，或直接装发行版的 RT 内核包（Ubuntu 用 `linux-lowlatency`）；`uname -r` 确认带 RT 标志。
- **验收**：装上 RT 内核后，cyclictest 最大延迟显著下降。

### 4.2 CPU 绑核与隔离
- **为什么要做**：避免调度器迁移导致缓存抖动、避免控制线程与其它任务争抢同一核。
- **工具/机制**：`isolcpus` 内核参数（启动时隔离核）、`taskset -c N`（绑线程）、cpuset cgroup、`numactl`。
- **验证**：`top`/`htop` 看某核是否空闲；`cat /proc/<pid>/status | grep Cpus_allowed_list` 确认绑核成功。
- **验收**：能把某线程固定到指定核，并验证该核上没有其它任务。

### 4.3 线程优先级与调度策略
- **调度策略**：SCHED_OTHER / SCHED_FIFO / SCHED_RR / SCHED_DEADLINE 的区别与适用场景。
- **API**：`sched_setscheduler`、`pthread_setschedparam`、命令行 `chrt -f 99`。
- **实时优先级**：范围、实时任务抢占普通任务的机制。
- **验收**：写两个线程（实时高优先级 + 普通低优先级），验证实时线程稳定抢占普通线程；设置 1kHz 控制线程为 SCHED_FIFO 高优先级，不被推理线程抢占。

### 4.4 内存与中断（进阶，抖动的隐形来源）
- **锁内存**：`mlock` / `mlockall`，防止缺页中断导致的不可控延迟。
- **IRQ 亲和性**：`/proc/irq/*/smp_affinity`，把高优先级中断（网卡、CAN 等）绑到非实时核，避开控制核。
- **大页内存**（可选）：减少 TLB 抖动。

### 4.5 实时性测量
- **cyclictest**（rt-tests 套件）：如何测最大/平均延迟与抖动、如何解读报告。
- **进阶**：`perf sched`、`trace-cmd` / `ftrace` 定位延迟来源。

**资源**：Real-Time Linux 官方 Wiki（preempt-rt）、Linux `man isolcpus/taskset/sched/chrt`、Robert Love《Linux 内核设计与实现》（调度器章节）。

## 模块五：多线程与 IPC（✅ 确定 · 主场 · 现在就练）

**目标**：推理线程（非实时、慢）与控制线程（实时、快）安全高效地分离与通信。

- **POSIX 线程（pthread）**：创建、属性设置、优先级。
- **同步原语**：互斥锁、条件变量、信号量；理解**优先级反转**问题及 PI mutex（`PTHREAD_PRIO_INHERIT`）的解决方式。
- **无锁队列 / 环形缓冲**：推理线程 → 控制线程的数据通道，避免加锁引入抖动（重点，练 SPSC 单生产者单消费者）。
- **共享内存 / 内存映射**：shm、mmap，跨进程大数据传递。
- **线程分离设计模式**：实时线程 vs 非实时线程的职责划分、数据流方向、缓冲策略（双缓冲/环形缓冲）。

**验收**：推理与控制两条线程分离跑通，推理产生的 action chunk 经无锁通道低抖动地送达控制线程。

### 综合练习：推理线程 + 控制线程分离原型（强烈推荐）

用纯 C/C++ 写一个 demo，把模块四 + 五串起来：

- **生产者线程**（非实时）：每隔一段随机时间（模拟 10–100ms 推理时延）生成假 chunk 放进无锁环形缓冲；
- **消费者线程**（实时，SCHED_FIFO 高优先级，绑核）：按 1kHz 固定周期从缓冲取 chunk，模拟控制环；
- 用 cyclictest / 自测脚本测消费者线程的**周期抖动**。

**为什么值**：不需要任何硬件/模型；直接就是论文"推理线程与控制线程分离"的原型；测出的抖动数据以后就是论文实验数据；后面换真硬件真模型时，只把"假生产者"换成"真推理"，框架不用重写。

## 模块六：SoC-MCU 异构协同与时延补偿（✅ 确定 · 主场）

**目标**：SoC（Orin 或 RK3588）跑慢而智能的策略，STM32 跑快而确定的 1kHz 伺服，协同闭环。

- **通信**：CAN / EtherCAT 基础、帧格式、实时性特点、波特率/周期选择。
- **电机伺服**：位置/速度/力矩环，1kHz 控制环的实现。
- **ROS2 基础**：节点、话题、DDS，以及 ROS2 在实时性上的限制（哪些部分要绕开）。
- **chunk 下发与 MCU 插值**：chunk 的数据格式（动作序列）、MCU 侧如何按控制周期插值执行（线性/多项式插值）。
- **时延补偿设计**：基于时延的补偿思路（参考 Smith 预估器的思想）、MCU 侧如何用时间戳补偿。
- **时间同步**：SoC 与 STM32 的时钟源、时间戳对齐。

**验收**：SoC 下发的 chunk 能在 MCU 上按 1kHz 平滑插值执行，闭环稳定。

## 模块八：时延调度与控制理论（✅ 确定 · 期刊核心）

**目标**：把"自适应 chunk + 事件触发"从工程技巧升级为有时延预算与误差界背书的调度策略。

- **时延预算建模**：在线估计 μ、σ、P99，算出安全时延预算 d_safe。
- **资源预留（resource reservation）**：budget / period 概念，把推理资源"预留"给控制环。
- **自适应 chunk**：把 chunk 长度从超参数变成运行时变量，按时延预算与任务动态度在线定长。
- **事件触发控制（ETC）**：状态偏差触发条件、事件触发 vs 周期触发的区别、Zeno 现象与避免。
- **网络控制系统（NCS）基础**：时延对闭环的影响、采样与时延的经典结论。
- **Lipschitz 连续性**：概念 + 如何在论文里一句话声明假设。
- **采样数据系统 + 时延的误差分析**：零阶保持 + 时延下的误差累积/上界推导（找 1–2 篇经典论文照着写）。
- **有界性 vs 稳定性**：理解你证明的是"误差有界"（boundedness），不碰"渐近稳定"。

**验收**：能写出"在 d ≤ d_safe 下，‖e(t)‖ ≤ L·(hT+d)+ε"这类误差界的完整推导，并能把调度参数（chunk 长度、事件阈值）与误差界定量挂钩。

**资源**：事件触发控制综述、网络控制系统综述、采样数据系统误差分析经典论文（从文献学，写清 difference）。
